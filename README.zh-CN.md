# ScreenSwitch · 内置屏幕开关

[English](README.md) | **简体中文**

一个中文 macOS 菜单栏小程序：MacBook 开盖、外接显示器工作时，由用户手动停用内置屏幕的桌面输出，保留内置键盘和触摸板。不使用亮度归零、黑色窗口或模拟合盖。

**重要：真正停用内屏没有 Apple 公开支持的接口。** 本程序动态解析私有函数 `CGSConfigureDisplayEnabled`，使用 CoreGraphics 显示配置事务的 `.forSession` 范围。接口存在或返回成功，不代表硬件实际关屏、背光熄灭和恢复均可用。失败时会明确提示并尝试恢复，不会以调暗屏幕冒充成功。此程序不保证兼容所有 macOS 版本和机型，不适合不能接受短暂黑屏或重启风险的场景。

## 启动和使用

从 [Releases](https://github.com/haroldvandy2013/ScreenSwitch/releases) 下载 `ScreenSwitch-v1.1.0-macos-arm64.zip` 并解压，包含主程序、应急恢复程序和中英文使用说明。发布包仅支持 Apple Silicon（arm64），未公证；**界面目前为中文，英文版仅指文档**。`SHA256SUMS.txt` 提供下载文件校验值：

```bash
shasum -a 256 -c SHA256SUMS.txt
```

请在压缩包所在目录执行校验。GitHub 提供的 “Source code” 下载是源码，不包含构建好的应用。

构建后的应用位于：

- `dist/ScreenSwitch.app`：主程序，有简单控制窗口、Dock 图标和菜单栏图标。菜单栏已满或被刘海遮住时，可直接使用控制窗口。
- `dist/恢复内置屏幕.app`：独立的应急恢复程序；主程序崩溃后也可运行，只发送开启内屏的请求。

双击 `ScreenSwitch.app`，或在此目录运行：

```bash
open dist/ScreenSwitch.app
```

1. 保持笔记本打开，连接并唤醒一个真实外接显示器，确认它正在显示可用桌面。建议首次使用原生 HDMI / USB-C / DisplayPort 连接。
2. 在控制窗口点击 **关闭内置屏幕**，或点击菜单栏的笔记本图标选择同名操作，阅读风险提示，再手动确认。无可用外屏、无法识别内屏或接口不可用时，两个入口均禁用。
3. 内屏关闭后，同一开关变为 **恢复内置屏幕**；另有一个始终可访问的恢复菜单项。
4. 最后一个可用外屏断开或不再活动时，程序尝试自动恢复内屏；多外屏时，仍有一个可用外屏就不触发恢复。
5. 外屏重新接入、系统唤醒不会自动关闭内屏。休眠前及正常退出时尝试恢复；无法确认恢复则取消正常退出，保留程序继续重试。

如需日常使用，可将**两个** `.app` 一起复制到 `/Applications` 或 `~/Applications`。本地构建使用临时（ad-hoc）签名，没有 Apple 公证；若系统阻止打开，请在 Finder 中右键应用选择“打开”，或使用系统设置中的“仍要打开”。不要关闭 Gatekeeper 或 SIP。不自动设置开机启动。

关闭控制窗口不会退出程序或停止安全恢复检查。点击 Dock 中的 ScreenSwitch、在 Finder 再次双击应用，或使用菜单栏的“显示控制窗口”，即可重新打开。应用处于前台时也可按 `Command + 0` 显示窗口；退出请使用“恢复屏幕并退出”或 `Command + Q`。

## 安全恢复

首次关屏前，请先熟悉应急恢复程序的位置。建议将其复制到应用程序目录并自行确认 Spotlight 能找到“恢复内置屏幕”。

若出现黑屏，依次尝试：

1. 接回并唤醒原来的外接显示器，在菜单中点击“恢复内置屏幕”。
2. 运行 `恢复内置屏幕.app`。如果 Spotlight 已经索引，可按 `Command + 空格`，输入“恢复内置屏幕”，回车。程序最多重试五次；失败会显示错误，不会声称已恢复。
3. 尝试合上再打开笔记本，让 macOS 重新识别屏幕；这不是保证有效的恢复方法。
4. 仍无效时，重新启动 Mac；会话级配置不用于永久修改显示器设置。只有在系统无响应时才考虑强制关机，避免未保存数据丢失。

终端手动恢复（**此命令会实际调用开启内屏的接口**）：

```bash
./dist/ScreenSwitch.app/Contents/MacOS/ScreenSwitch --restore
```

该命令仅恢复，绝不关闭内屏；成功退出码为 `0`，失败为 `1`。程序不提供命令行关屏选项，避免脚本误触发。

**恢复边界：** 程序使用底层显示重配置回调、AppKit 显示变化通知和每秒检查，发生拔线后会有检测及系统重配置延迟。拔线与关屏提交之间无法做到硬件级原子操作。强制退出、进程崩溃、系统卡死、驱动问题或私有接口失效时，自动恢复不能绝对保证，也没有常驻 root 服务兜底。程序会在关屏前持久化内屏标识与待恢复标记，下次启动发现未完成的恢复时优先尝试开启内屏，而不是继续关屏。

不要同时运行其他停用显示器的软件。程序不会将系统或其他软件已经恢复的内屏再次自动关闭。外屏是否“可用”依据 CoreGraphics 在线、活动、未休眠及有效尺寸判断；这不能可靠证明它是实体屏、用户确实看得见桌面，或线缆/转接器正常。不应将 AirPlay、虚拟显示器、远程桌面或 DisplayLink 当作唯一恢复保障。镜像模式和各类扩展坞也需要实机验证，首次使用建议选择扩展桌面模式。

## 从源码构建

要求 macOS 13 或以上、Swift 6.0 或以上；无需第三方依赖。安装 Xcode Command Line Tools 后：

```bash
git clone https://github.com/haroldvandy2013/ScreenSwitch.git
cd ScreenSwitch
./build.sh
```

脚本编译发布版本、打包上述两个 `.app` 并进行 ad-hoc 签名。默认生成本机架构，不是 Universal 二进制。主应用和应急恢复应用使用同一可执行文件，通过不同的 bundle ID 选择入口。

安全检查：

```bash
# 纯策略组合检查，不链接任何显示控制代码
swift run --quiet ScreenSwitchChecks

# 实际控制器的模拟生命周期检查；不会创建真实 DisplayDriver
swift run --quiet ScreenSwitch --check-controller

# UI 入口检查：显示/关闭/重新打开窗口，不点击关屏
# 如果之前关屏留下待恢复标记，会按正常启动规则尝试恢复
swift run --quiet ScreenSwitch --check-ui

# 实际系统的只读诊断：枚举显示器、解析符号，不发送显示配置事务
./dist/ScreenSwitch.app/Contents/MacOS/ScreenSwitch --diagnose

codesign --verify --deep --strict dist/ScreenSwitch.app
codesign --verify --deep --strict 'dist/恢复内置屏幕.app'
```

安全检查使用无第三方依赖的 Swift runner，适用于仅安装 Command Line Tools、没有 XCTest 模块的环境。它们覆盖安全条件组合，以及手动开关、最后一个外屏拔除、保留一个外屏、重接不关屏、休眠唤醒、延迟生效竞态、接口空操作、恢复失败持续重试、异常退出标记和系统自行恢复等模拟路径；不等同于硬件测试。

`--check-controller` 和 `--check-ui` 只在 Debug 构建提供；发布版拒绝这些选项。

菜单中的“复制只读诊断”提供相同的基本系统信息。错误写入 macOS 统一日志，子系统为 `local.ScreenSwitch`。恢复状态保存在当前用户的 `local.ScreenSwitch.recovery` 偏好域；不要在内屏关闭时删除它。

## 本次验证与尚需确认的事项

开发环境为 **Apple M3 Max（Mac15,11）、macOS 15.8.1（24H32）、Swift 6.1.2**。已安全确认当前系统能解析所需私有符号、识别活动内屏；当前没有在线外接显示器。关屏交易只在用户点击并确认后发起。

已通过 262 项策略组合检查、26 项模拟控制器生命周期检查，以及窗口启动、共享安全状态、关闭后重新打开的 UI 检查；两个 arm64 `.app` 已完成发布构建及签名校验。主程序已实际启动，提供 Dock 入口和可见控制窗口，同时保留菜单栏入口；启动后的内屏仍处于活动状态。

**未自动进行真实关屏或恢复交易。** 因此以下事项仍须用户在外屏连接后自行实机确认：

- 内屏确实不再参与桌面输出，而不只是变黑；背光是否熄灭、窗口和鼠标是否仅保留在外屏。
- 关屏后内置键盘、触摸板可继续使用（本程序不修改任何输入设备设置）。
- 手动恢复、最后一个外屏拔线恢复、休眠唤醒和退出恢复，在具体外屏与转接器上是否可靠。
- 应急恢复应用、多个外屏、镜像模式及其他 M3 Pro / Max 机型是否兼容。

基础款 M3 的已知显示限制不能直接推论到 M3 Pro / Max，但后者同样不能凭符号解析成功就宣称兼容。若首次手动关屏失败，请停止继续关屏，保留诊断信息，不要尝试修改系统安全设置。
